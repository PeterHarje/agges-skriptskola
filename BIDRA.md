# Bidra till AggEs skriptskola

[← Till skriptskolans startsida](README.md) · [Lärarhandledning](for-larare.md)

Tack för att du vill göra programmering lättare att förstå!

Vi bygger för **nyfikna nybörjare, elever, lärare och självlärda programmerare**. Viktigast är att deltagaren förstår vad koden gör – inte att exemplen är långa eller imponerande.

## När du föreslår ett nytt kapitel

1. **Bestäm kunskapsnivå:** 0 (helt ny), 1 (nybörjare), 2 (fortsättning) eller 3 (fördjupning).
2. **Ange förkunskaper och mål:** Vad ska läsaren kunna innan? Vad ska hen kunna efteråt?
3. **Visa ett kort fungerande exempel:** gärna färre än 20 rader åt gången.
4. **Förklara kommandona:** Vad gör de, varför behövs de och vilka delar är viktiga?
5. **Beskriv riskerna:** Läser eller skriver koden? Kräver den särskilda rättigheter?
6. **Ge minst en övning:** Låt läsaren ändra en detalj och se vad som händer.
7. **Ge ett enkelt självtest:** Kan läsaren förklara koden med egna ord?
8. **Länka rätt:** Från startsidan, från relevant nivå och från [kommandoindex](05-ordlista.md).
9. **Testa dina exempel:** Skriv vilken version av operativsystem/program som användes och vad som faktiskt testats. Påstå inte att otestad kod är verifierad.

## Mall för lektion

Använd gärna den här ordningen:

~~~text
# Titel på lektionen
Nivå:
Förkunskaper:
Ungefärlig studietid:
Mål:

## Vad ska vi lösa?
## Först: förstå idén
## Kort kodexempel
## Rad för rad – vad händer?
## Vad kan gå fel?
## Öva själv
## Självtest
## Nästa steg
~~~

## Skriv till människor, inte bara till utvecklare

- Använd enkel och tydlig svenska. Förklara engelska fackord första gången.
- Ha ett mål per övning. Spara sidospår till egna kapitel.
- Gör det möjligt att läsa lektionen **utan att vara inloggad i någon tjänst**.
- Uppmuntra frågor, omtag och egen takt. Ingen ska behöva känna sig dum.
- Använd gärna vardagliga exempel – musik, textfiler, små beräkningar eller datorfelsökning – utan privata data.

## Håll offentligt material säkert

Inga produktionsnycklar, lösenord, autentiseringscookies, privata kunduppgifter eller interna sökvägar ska publiceras. Lägg inte in företagets interna tekniska dokument bara för att de finns i en privat utvecklingsmiljö.

Övningar bör vara läsande eller arbeta på frivilligt skapade testfiler i en avskild katalog. Undvik kommandon som kan radera data, stänga av skydd eller ändra systeminställningar om det inte finns ett särskilt genomarbetat och säkert pedagogiskt sammanhang.

Du kan föreslå förbättringar via ett GitHub Issue eller Pull Request när repots inställningar tillåter det. Var konkret: vilket kapitel, vilken rad, vad förvirrade dig och hur kan det bli tydligare?
